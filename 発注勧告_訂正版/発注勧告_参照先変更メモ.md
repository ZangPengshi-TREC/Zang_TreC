# 発注勧告IF 参照先変更メモ

## 変更結論

発注勧告IFの比較対象を、従来の **CoreSaver数理発注データ** から
**`SIREJAN_RCMDORDER_LAST`** に変更する。

- Label：`SIREJAN_RCMDORDER_LAST`
- Note：`仕入JAN_最終推奨数の反映`
- KEY：`BranchCD` ＋ `SireJAN`
- 参照日：2026-09-04

従来資料にある `sets`、`cost`、`price`、`odunit_qy`、`odr_kbn_typeid`、
`depocd`、`logi_type` 等の CoreSaver 固有項目は、今回の比較対象から外す。

## 新しい参照レイアウト

| No. | 項目 | Field name | Type | 形式 | 桁数 |
|---:|---|---|---|---|---:|
| 1 | 店舗CD | `BranchCD` | KEY | 固定長 | 4 |
| 2 | 仕入発注JAN | `SireJAN` | KEY | 固定長 | 20 |
| 3 | 推奨発注数量 | `SireJAN_rcmd_end` | VALUE | 可変長 | 0 |
| 4 | ベンダーCD | 記載なし | VALUE | 固定長 | 8 |
| 5 | 納品日 | `ShippingDate` | VALUE | 固定長 | 8 |
| 6 | Ordertype | 記載なし | VALUE | 固定長 | 1 |
| 7 | 更新日 | 記載なし | VALUE | 固定長 | 8 |

> 画像に記載のない物理編集規則、Ordertypeの値定義は推測せず、
> GAPとして確認する。

## 暫定マッピング

### 店舗系（kankoku / subkankoku）

- `BranchCD` ← No.1 店舗コード
- `SireJAN` ← No.3 商品コード
- `SireJAN_rcmd_end` ← **No.11 発注バラ数**
- ベンダーCD ← No.6 仕入先コード
- `ShippingDate` ← No.4 納品日
- Ordertype ← 対応元なし。固定値または導出
- 更新日 ← No.2 発注日（候補）

数量関係：`No.11 発注バラ数 = No.12 発注単位数 × No.15 発注単位`

### 倉庫系（ka / subka）

- `BranchCD` ← ファイル名の倉庫コード（候補）
- `SireJAN` ← No.7 品番
- `SireJAN_rcmd_end` ← **No.11 バラ換算数量**
- ベンダーCD ← No.3 仕入先コード
- `ShippingDate` ← No.14 納品日
- Ordertype ← 対応元なし。固定値または導出
- 更新日 ← No.1 発行日（候補）

数量関係：`No.11 バラ換算数量 = No.9 注文数量 × No.12 発注ロット`

倉庫系については、対象表の項目意味が「店舗CD」であるため、
`SIREJAN_RCMDORDER_LAST` 自体が適用対象かを先に確認する。

## 重要な訂正

推奨発注数量について、従来の
`sets = バラ換算数量 × 1000` は CoreSaver向けの変換であり、今回の参照先には適用しない。

`SIREJAN_RCMDORDER_LAST` の推奨発注数量は、発注単位調整後の数量であり、
発注単位の整数倍となる。そのため、次のマッピングで確定する。

- 店舗系：No.11 発注バラ数
- 倉庫系：No.11 バラ換算数量
- 変換：整数値を直接設定し、**1000倍しない**

No.12 発注単位数／No.9 注文数量は箱数のため、直接マッピングしない。
