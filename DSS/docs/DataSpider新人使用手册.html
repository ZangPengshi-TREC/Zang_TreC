DSS 在西友数据联动里干什么

DSS 是系统间 EAI/ETL，不是分析仓。选型见ガイドライン P.18。高 Tier 用 DataHub；分析积蓄用 Databricks；DSS 适合中低 Tier 的文件 / DB 联动。

方案主要用途
DataHub高 Tier、要冗余的文件联动
DataSpider系统间文件 / DB
Databricks积蓄、分析。写仓走 ADLS（MS0007）
Lakehouse Federation只参照外部最新状态。注意源库负荷

ADLS：一 IF 一容器，外部用 SFTP，约 30 天后自动删。数据质量：先约定编码、全角半角；乱码当损坏处理。

Day1 三个演示

① CSV 转换集计

输入 OrderList.csv（受注日、支店、ケース数、入り数、容量、商品名、受注_ID）。按支店汇总发注数，写出 OrderList_total.csv。变换放 Mapper，不要用 IF/循环逐行加工。

② 0 件当错误

只有表头、没有数据行。不写输出文件，主动结束成错误。接到框架后，这就是警告或 255。

③ 文件触发器

把 CSV 放到输入文件夹 → 自动跑① → 结果进输出文件夹。触发器挂的是已注册服务，不是未登记脚本。

服务注册：项目右键「プロジェクトをサービスとして登録」。画面会比较源项目和目标服务的脚本。

正式开发必须按框架 个别脚本只做事、设 End 戻り値，不要自己发邮件。触发器永远调 SEIYUCOM000X / 01frameworkBatch。

四条收口（Day2 核心）

戻り値设在 End 组件的属性检查器里，不是脚本属性随便写一个数。

分支你的脚本怎么结束框架做什么
1 正常End 戻り値 0记成功日志后结束
2 警告戻り値 1–254（演示：CSV 只有表头 / 0 件）警告邮件 + 警告日志
3 可控异常戻り値 255，并且填了 out_*异常邮件 + 异常日志
4 未捕获Exception / 没 catch框架 catch 后发异常邮件。戻り値实际是 -1

警告/异常用「警告变量设定」「异常变量设定」填 out_component_name/type、out_message_*、out_error_*。邮件后半段例如：

FILE0001E|java.io.FileNotFoundException|/data/DSSROOT/DEMO/INPUT/OrderList.csv|CSV読取

改写口径：正常 = 跑完（0）；警告 = 0 件（1–254）；异常 = 读或写失败（255 + out_*）。

发布（リリース手順書 v1.0）

用资源管理员登录目标环境 顺序：项目 → 非项目资材 → 系统表。STG/PROD 走 SDP；监视提前约 1 周找 ITSM。

5.1 项目 zip

  1. マイプロジェクト → ローカルへダウンロード。勾选「バージョンを指定してダウンロード」，选数字最大的最新版。
  2. 目标：ローカルからアップロード。上書き = 作为现有项目最新版；换名 = 另起项目。
  3. 打开 → 服务注册（服务名 = 项目名）→ マイサービス确认。
  4. zip 不带共享。STG/PROD 上传后：共有 → SY 组读取。一览要能看到「共有」。
  5. 脚本写 Explorer 文件夹时，给 exec_SY 加写入组权限（P.110）。

5.2 非项目（サーバ移行）

  1. コントロールパネル → DataSpiderServerの設定 → サーバ移行。
  2. 导出先「全て解除」，只勾本次要搬的。
  3. 导入不要去掉「プロジェクトの差分インポート」和「環境変数の差分更新」。去掉会整表覆盖。
  4. 导入后重启 Windows 服务 DataSpiderServista。
  5. 同名时：服务/触发器/全局资源覆盖；环境变量和项目文件可跳过。用户逻辑冲突会改成 name_1。

5.3 系统表

只搬项目不够。改 if_master 前必须备份。

方式步骤
CSV 备份SELECT 对象表 → 結果に名前を付けて保存

接口形态 一个 IF = 一个处理单位（同一 IF 可传多个文件）。只做单体。ガイドライン还有バラマキ / 数珠繋ぎ / 複数，西友只用単体。数珠つなぎ禁止。不要从 Designer 直接调生产脚本。
