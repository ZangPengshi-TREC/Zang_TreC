# DD-00 Common Interface Design

Version: 0.4 draft
基準日: 2026-09-11（方針更新 2026-09-22：申請図・landing＝本PJ附帯GCS／output＝西友連携GCS・起動 TBD）
適用範囲: 自動補充 Sinops-01〜25
対象外: BO 系、Hitluster/WMS、棚割システム本体

## 1. 目的

Phase 1 の IF ごとの Mapping / GAP / 変換ルールを、実装・単体テストから参照できる共通方式へ整理する。個別 IF に同じコード変換、対象範囲、エラー処理を重複記載しない。

## 2. 確定度の記号

| 記号 | 意味 |
|---|---|
| CONFIRMED | 残課題表または合意資料で確定しており、根拠を追跡できる |
| ASSUMPTION | 詳細設計を進めるための暫定仮定。製造前に根拠を得る |
| TBD | 入力資料に回答がなく、値を決めてはいけない |
| OUT | 本フェーズの対象外 |

## 3. 共通処理方針

### 3.0 Layer 分担（CONFIRMED）

**原則: DataSpider（Layer②／③）では型変換もフィールド選別も行わない。全フィールドを通す。型変換・項目選別・コード変換・編集は Layer①（SCM連携クラウド機）で行う。**

| 層 | やってよいこと | やってはいけないこと（原則） |
|---|---|---|
| **Layer①** | 抽出、共通化、**型変換**、**フィールド選別／絞り込み**、コード変換、編集・生成、プッシュ／プル | （本機に永続ステージングを置かない、等は別則） |
| **Layer②** | GCS → DWH の **全項目 Intake**（受け渡し） | 型変換、項目ドロップ、コード変換、業務編集 |
| **Layer③** | 業務システム ↔ GCS／DWH の **転送・配置**（全フィールド） | 型変換、項目選別、コード変換・編集してレイアウトを作り込む |

例外が必要な場合は IF ごとに TBD を起票し、承認されたものだけを CONFIRMED 例外とする。默認は上表。

## 4. 共通コード変換

### 4.1 店舗コード

変換テーブルの論理項目は `Sinops店舗コード`、`TRIAL BranchCD`、店舗名称、適用期間、確認状態とする。変換テーブルに存在しないコードは、名称類似で補完せずエラーとする。西友店舗コード一覧が配布された時点で、変換テーブルの有効期間と廃止コードの扱いを追加する。

### 4.2 商品コード

現行 Phase 1 草案は次の順序である。

1. 入力値を文字列として trim する。
2. JAN の右端 13 桁を取得する。
3. 桁不足、空値、13 桁以外の入力をエラーまたは例外許可へ振り分ける。
4. 対象商品判定後、出力する。

手順 3 の最終判定、先頭 0 の保持、インストアコードの扱いは商品マスタ統合 PJ と G-01 の決定を待つ。

### 4.3 分類コード

Master 統合側のシート別キー、型、桁、データ元、残課題との矛盾は `master-integration-structure.md` に集約する。

## 5. 共通検証とエラー分類

| 検証 | エラー分類 | 処理草案 |
|---|---|---|
| 必須項目が空 | E001 | レコードエラー。出力せず件数とキーを記録 |
| 型/桁不正 | E002 | レコードエラー。数値変換前の元値を記録 |
| コード変換テーブル未登録 | E003 | レコードエラー。名称による推測変換は禁止 |
| JOIN 元が複数件 | E004 | レコードエラー。勝手な先頭 1 件採用は禁止 |
| 同一キー重複 | E005 | IF の洗い替え/差分仕様に従い、許容またはファイルエラー |
| ファイル形式不正 | E006 | ファイルエラー。後続処理を起動しない |
| 件数/完了通知不整合 | E007 | ジョブ異常。再送判断を運用へ連携 |

E001〜E007 の終了コード、ログ保存期間、通知先、再送操作は共通運用設計で確定する。現時点では値を実装へ埋め込まない。

## 6. 共通単体テストの最低セット

- 正常 1 件、正常複数件、0 件
- 必須欠損、空文字列、NULL、0 の各ケース
- 先頭 0、右端 13 桁、桁不足、桁超過
- コード変換テーブル登録済み/未登録
- 重複キー、JOIN 複数件、対象外レコード
- 全件洗い替え、差分更新、同一ファイル再送
- 正常終了、レコードエラー、ファイルエラー、再送後の結果

## 7. 未確定事項の管理

未確定事項は `traceability-matrix.csv` のゲートと決定 ID に紐付ける。決定が出た場合は、共通方式、該当 IF の項目仕様、変換ルール、単体テストの 4 箇所を同じ決定 ID で更新する。
