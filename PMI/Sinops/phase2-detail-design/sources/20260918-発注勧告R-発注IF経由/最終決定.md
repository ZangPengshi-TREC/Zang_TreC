## 1. 決まったこと

店舗系発注勧告の**ファイル契約**は、CoreSaver 数理発注データ比較でも OrderSV 店別テーブルでもなく、**発注IF `SIREJAN_RCMDORDER_LAST`** である。

層の分担（発注勧告 R）:

| 層 | 担当 | 経路 |
|---|---|---|
| Layer③ | 西友 Azure DataSpider | Sinops → DSS 処理 → **連携用 GCS** |
| Layer① | IFクラウド機（SCM連携クラウド機） | 連携用 GCS → IFクラウド機で処理 → **TRIAL 自動発注 GCS** へアップロード |

Sinops は連携用 GCS へ直送しない。DSS も TRIAL 自動発注 GCS / OrdreSV へは送らない。自動発注 GCS 以降の既存転送 → OrdreSV は 403 の③ではない。

IFクラウド機が作るファイルは、この 7 項目レイアウトに合わせる。

確定ルール:

| ID | 内容 |
|---|---|
| R01 | 参照先を CoreSaver 比較から `SIREJAN_RCMDORDER_LAST` へ変更 |
| R04 / G04 | 推奨発注数量 = 店舗系 No.11 発注バラ数を直接設定。発注単位調整後のバラ総数。×1000 しない |
| R06 | 納品日 = yyyymmdd 固定長 8。sinops No.4 をそのまま |

訂正文（マッピング表）: CoreSaver 数理発注データとの比較を廃止。
