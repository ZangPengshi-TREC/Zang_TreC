### 【スライド 1】背景・なぜ新しいクラウド機を申請するか　／　翻到第 1 页

#### 中文

各位好。今天说明 **SCM連携クラウド機** 的 GCP 环境申请。一共七页：先讲背景，再讲为什么用 Cloud Run，然后是构成、每天怎么跑、规格、费用，最后和 GKE 对比。

先看背景。现在推进的是西友与 TRIAL 的 **MD 基幹統合、自动补充 Sinops 第二阶段**。每天要把大阪集计侧的数据交到西友侧；公司之间的正本通路是西友连携 GCS。型转换和共通化，方针上放在 TRIAL 侧吸收。如果按课题拆多个项目，SCM 统一连携面会裂开，所以要收敛成一台机。

因此需要：在 TRIAL GCP 上申请 **一台 SCM 连携机**；负责见积里的 **Layer①**——取得、转换、配置的批处理；附带 GCS（源数据）和 Cloud Run（处理）一体申请；只把最终 TXT 单方向交到 Seiyu GCS。位置上，和现有的惣菜、MD-Link、Inunaki 并列。

为什么说是「新机」。Layer① 是这次要申请的 TRIAL 云机；Layer②③ 是西友 Azure 的 DataSpider，**另案 Spec**。DSS 只做全字段通过，转换在 Layer①。本机不挂持久盘，永续只在 GCS。这也是 Sinops 见积约四百零三人日的执行基盤前提。

申请什么、不申请什么。申请：一个项目、Cloud Run Jobs、自有 GCS、Scheduler、Workflows、STS 等。不申请：GKE、本机持久磁盘、DataSpider、以及西友连携 GCS 本体——连携 GCS 要向松尾另行申请。

一句话：**为了跑通公司间自动补充连携，TRIAL 侧需要带转换的统一 IF 基盤，所以申请新建一台 SCM連携クラウド機。**

接下来讲，这台机用什么执行基盤。

#### 日本語

みなさま、本日（ほんじつ）は **SCM連携クラウド機** の GCP 環境（かんきょう）申請（しんせい）をご説明（せつめい）します。全（ぜん）7 枚（まい）です。背景（はいけい）、Cloud Run 採用（さいよう）理由（りゆう）、構成（こうせい）、日次（にちじ）の動（うご）き、スペック、費用（ひよう）、最後（さいご）に GKE 比較（ひかく）の順（じゅん）です。

まず背景です。いま進（すす）めているのは、西友（せいゆう）と TRIAL の **MD 基幹（きかん）統合（とうごう）・自動補充（じどうほじゅう）Sinops 第（だい）2 段階（だんかい）** です。大阪（おおさか）の集計（しゅうけい）系データを日次で西友側へ渡す必要があり、会社間（かいしゃかん）の正本（せいほん）通路（つうろ）は西友連携（れんけい）GCS です。型変換（かたへんかん）と共通化（きょうつうか）は TRIAL 側で吸収（きゅうしゅう）する方針（ほうしん）です。課題（かだい）ごとにプロジェクトを割（わ）ると SCM の統一連携面が割れるため、1 台（だい）にまとめる必要があります。

そのため必要なのは、TRIAL GCP 上の **SCM 連携機を 1 台**。見積（みつもり）の **Layer①**、つまり取得（しゅとく）・変換・配置（はいち）のバッチです。附帯（ふたい）GCS（源データ）と Cloud Run（処理）を一体で申請し、最終（さいしゅう）TXT のみ Seiyu GCS へ単方向（たんほうこう）納品（のうひん）します。位置づけは、既存（きそん）の惣菜（そうざい）・MD-Link・Inunaki と並列（へいれつ）です。

なぜ「新しい機」か。Layer① が今回申請の TRIAL クラウド機、Layer②③ は西友 Azure の DataSpider で **別 Spec** です。DSS は全フィールド通過、変換は Layer①。本機（ほんき）に永続（えいぞく）ディスクは持たず、永続は GCS のみ。Sinops 見積おおよそ 403 人日の実行前提となる基盤でもあります。

申請する／しない。申請するのは 1 プロジェクト、Cloud Run Jobs、自有 GCS、Scheduler、Workflows、STS など。申請しないのは GKE、本機永続ディスク、DataSpider、西友連携 GCS 本体です。連携 GCS は松尾さんへ別途申請します。

一口で言うと、**会社間の自動補充連携を回すため、TRIAL 側に変換付きの統一 IF 基盤が要る。だから新規 1 プロジェクトの SCM連携クラウド機を申請する**、です。

次に、この機をどの実行基盤で作るかを説明します。

### 【スライド 2】なぜ Cloud Run Jobs を採用するか　／　翻到第 2 页

#### 中文

第二页是技术判断。本件不是常驻 API，而是 **需要时才跑的日次文件 IF 批处理**。所以用 **Cloud Run Jobs**，**不上 GKE**。

四个観点。一，動き方：启动→处理→结束，空闲可停；GKE 容易常设集群，批处理易留固定费。二，工作内容：抽出、转换、GCS 推拉；GKE 更适合微服务和常驻 API。三，存储：无状态、正本只在 GCS；GKE 往往带节点和卷运维。四，运维费用：Cloud Run 轻；GKE 有集群费，后面用数字对照。

收束：**不是常开的底座，而是需要时才跑的批处理，所以用 Cloud Run Jobs。**

接下来看构成图。

#### 日本語

2 枚目は技術（ぎじゅつ）判断（はんだん）です。本件は常駐（じょうちゅう）API ではなく、**必要なときだけ動く日次ファイル IF バッチ**です。そのため **Cloud Run Jobs** を採用し、**GKE は申請しません**。

観点は四つ。第一、動き方：起動→処理→終了、遊休時は止められる。GKE はクラスタ常設しやすく固定費が残りやすい。第二、仕事：抽出・変換・GCS プッシュ／プル。GKE はマイクロサービス向き。第三、ストレージ：無状態、正本は GCS のみ。GKE はノード／ボリューム運用が前提になりやすい。第四、運用・費用：Cloud Run は軽い。GKE はクラスタ費があり、数字は後で対比します。

**常時動かす基盤ではなく、必要なときだけ動くバッチなので Cloud Run Jobs**、です。

### 【スライド 3】申請構成図　／　翻到第 3 页

#### 中文

第三页是构成。申请东京 `asia-northeast1` 自有 GCP，dev／stg／prod。暂定 ID **md-data-integration-prod**。Layer①＝附带 GCS＋Cloud Run 一体。

左：大阪集计 GCS（既存、不申请）日次数据＋`_READY`。中：STS 复制到自有 `source-landing/`（约七天），Cloud Run **4 vCPU／16 GiB** 做 SMART，只把最终 TXT upload。右：Seiyu 专用 GCS 的 `result/`＋`_SUCCESS`。

控制：Scheduler → Workflows（READY→STS→Job→验证）。安全边界：**源数据不进 Seiyu GCS**；西友只有 objectCreator。大文件流式＋resumable；必要时临时盘外排。无 GKE、无本机持久落地。

#### 日本語

3 枚目は構成図です。東京 `asia-northeast1` の自有 GCP、**dev / stg / prod**。暫定 ID は **md-data-integration-prod**。Layer①＝附帯 GCS＋Cloud Run の一体です。

左は大阪集計 GCS（既存・今回申請しない）、日次データ＋`_READY`。中央で STS が自有 `source-landing/`（約 7 日）へコピーし、Cloud Run **4 vCPU / 16 GiB** が SMART 処理、最終 TXT のみ upload。右は Seiyu 専用 GCS の `result/` と `_SUCCESS`。

制御は Scheduler → Workflows（READY→STS→Job→検証）。安全境界：**源データは Seiyu GCS に入らない**。Seiyu は objectCreator のみ。大容量はストリーム＋resumable。GKE と本機永続ステージングは持ちません。

### 【スライド 4】日次実行フロー・権限・処理方針　／　翻到第 4 页

#### 中文

第四页：每天六步——Scheduler → READY／manifest → STS → Cloud Run → 纳品 TXT → `_SUCCESS`。SMART 链：解压、选列行、外排 JOIN、汇总、计算格式、stream uploader。

大文件不整进 RAM；权限 STS 大阪读／自有写，Job 自有读／Seiyu 仅 objectCreator；容量约 251.6 GiB（七天）、転送约每月 1,078 GiB；费用初算约 **一万八千一百九十日元**（第六页明细）。

#### 日本語

4 枚目は日次 6 ステップです。Scheduler → READY／manifest → STS → Cloud Run → TXT 納品 → `_SUCCESS`。SMART は解凍・selcol／selrow・外排 JOIN・集計・format・stream uploader。

大ファイルは RAM に全量を載せない。権限は STS＝大阪 read／自有 write、Job＝自有 objectViewer／Seiyu objectCreator のみ。容量は源データ約 251.6 GiB（7 日）、転送月約 1,078 GiB。費用初算は約 **1万8,190 円**（明細は 6 枚目）。
