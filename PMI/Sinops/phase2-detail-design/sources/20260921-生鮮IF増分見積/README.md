## 0. 見積前提（必読）

**提示値は先方協議の流用結果を仮置きした工数**（確定請負ではない）。  
当社はその協議に同席していない。実データでの流用可否は未確認。B1（流用確認と残件）突合で確認し、覆ったら再見積。  
ほか残るのは水煮相当・GCS実作業・伝票区分精査・生鮮勧告→発注統合変換の項目差・**入荷予定・発注スケジュールのSQL取得と生鮮データ作成時刻**。

判定の要点:
- 店舗系マスタ・実績 **12本は先方協議では非生鮮と同じ（流用）。当社未確認**
- 発注勧告当日／翌日以降は **Sinops勧告の2ファイル、工数は1.5本**（翌日は当日類似で0.5本）
- **発注統合向け変換も新規**（生鮮勧告→発注統合変換）。現行の生鮮→発注統合IFは使えない。非生鮮発注勧告を参照して作り直す
- 入荷実績はベンダー流用、**伝票区分差分、PC/CKは振替**
- 入荷予定・発注スケジュールはベンダー流用。**PC/CKの生鮮データは別SQL。Layer①でDBGET**
- 倉庫系は **DC在庫なし → 対象外**
- 残件: 倉庫商品マスタ（TRIAL青果水煮相当）。要IFなら再見積
- **作成時刻**は標準案で待ち合わせを含む。日次で大きくずれる場合は再見積

## 7. 説明話術の作り方（今後の共通ルール）

今後、本フォルダおよび類似の説明話術を作るときは次を守る。

1. **中日双语**：同じ節に中文（照着念／要点）と日文（対外読み上げ）を並記する  
2. **日文の振り仮名**：漢字はできるだけ読みを付ける（Markdown は `漢字（かな）`、HTML は `<ruby>`）。常用のひらがな・カタカナ・英数字はそのまま  
3. **成果物は2形式**：`.md` と `.html` を必ずセットで出す  
4. **用語**：簡体字混入禁止（例：一览→一覧、精查→精査）。中語直訳を避ける（双源→2系統ソース、着地→連携先、上げ→アップロード、未凍結→未確定）  
5. **範囲の言い切り**：Phase2＝詳細設計・開発・単体まで。結合以降は「含まない」と明示  
6. **記号は必ず言い切る**：人日の前に **A（確定した新規／差分IF）／B1（流用確認と残件）／B2（マスタ本体IF）／B3（非生鮮Phase2への波及）／C（増分PJ管理按分）** と読む。略号だけ読み上げない
