# Master Integration Structure Baseline

Version: 0.1 draft
基準日: 2026-09-11
対象: 自動補充 Sinops 系の入力 Master 統合
対象外: BO 系、WMS 本体、棚割システム本体

## 1. 指示と参考資料の区分

| 区分 | 内容 | 扱い |
|---|---|---|
| ユーザー要求 | 自動補充の詳細設計を進める。BO は当方の担当外として除外する | 本書のスコープを決める指示 |
| 参考資料 | `詳細設計向けのため要解決の残課題一覧(Sinops).xlsx` | 未決事項、回答、候補案の根拠。回答欄を無条件に確定仕様へ昇格させない |
| 参考資料 | `標準外部IFレイアウト_出力_マスタ.xlsx` | Master 統合の構造、項目名、型、桁、キー、データ元の根拠。Sinops の出力仕様そのものではない |

## 2. Master 統合資料の性格

`資料説明` では、本資料を PKG の DB テーブルをベースにした「標準外部 IF レイアウト」と説明している。項目の有無を現行外部 IF と Fit & Gap し、項目 No が入っているものを出力対象とする構成である。

したがって、本資料から確定できるのは「統合 Master 側にどの項目が存在し、どの型・最大長・キー・データ元を持つか」である。Sinops の項目への最終マッピング、抽出条件、税区分、運用主体は、Phase 1 の IF 資料と残課題の決定 ID で別途確定する。

## 4. 詳細設計で再確認する構造矛盾

| ID | 論点 | 資料間の差異 | 設計扱い |
|---|---|---|---|
| MSTR-01 | 仕入先コード桁数 | 残課題 No.8 は西友 9 桁コードを移行する回答。一方、`取引先マスタ.code`、`商品調達マスタ.vendor_id`、`発注締時間マスタ.vendor_id` は最大 8 桁 | 要再確認。9 桁をどこで保持し、Sinops へ何桁で出すか決定するまで `CONFIRMED` にしない |
| MSTR-02 | 商品分類投影 | 旧 Phase 1 資料の階層対応と、追加版の `base_org`/`base_div`/`base_line`/`base_upper1`〜`5` の関係が同一表で確定していない | 要再確認。意味対応、出力桁、ゼロ埋め、上位階層の採用範囲を同じ決定 ID で確定する |
| MSTR-03 | 売価の税区分 | 残課題 No.6 は売価税込・原価税抜。一方、`店舗商品マスタ` は税抜 `price` と税込 `price_intax` の両方を持つ | 要再確認。Sinops 出力項目の税区分、税率参照、端数処理を確定する |
| MSTR-04 | センターキーの表現 | `商品調達マスタ`/`店舗商品マスタ` の `center_id` は `char` 最大 6。一方、`納品先センター.center_id` は `int32_t` 最大 5 | 要再確認。コード変換テーブルの論理型、先頭 0、表示コードを確定する |
| MSTR-05 | 自動発注対象フラグ | 残課題 No.17 は自動発注システムからの連携案。Master 構造には `商品自動発注制御マスタ.f_at_odr` があるが、保持元と更新タイミングは未確定 | 要再確認。Shinise/自動発注システム/Master のどれを source of truth とするか決定する |

## 5. 詳細設計への適用ルール

1. 商品共通の分類は `商品共通マスタ（商品分類項目追加版）` を最新候補として参照し、旧版の `base_upper1`〜`4` をそのまま実装しない。
2. 店舗別発注情報は `店舗商品マスタ` を主入力候補とし、原価・入数・便・センター・発注期間・削除を一つのキー体系で設計する。
3. 仕入先コード、売価税区分、センターコード、自動発注対象フラグは、Master 構造だけで確定したことにしない。MSTR-01〜05 の決定を待つ。
4. `棚マスタ`、`棚割変更ヘッダ`、`店舗棚割変更指示` 等は棚割システム本体の設計・開発には使用しない。Sinops-14/15 で必要な受信項目、更新タイミング、欠損時処理だけを外部依存として管理する。

## 6. 次の設計作業

1. `DD-00` の商品キー、仕入先キー、分類コード、センターキーを MSTR-01〜04 に紐付ける。
2. `DD-01` の item/store item の入力元を、旧 Phase 1 名称から Master 統合シート名と項目 ID へ置き換える。
3. No.16/17/18 の発注締時間、自動発注対象、便区分を、発注締時間・自動発注制御・商品調達のキーで横断確認する。
4. 決定が出た項目だけを `CONFIRMED` に昇格し、項目仕様、変換ルール、単体テストを同じ決定 ID で更新する。
